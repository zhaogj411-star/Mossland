# 代码索引

Mossland 当前包含 agent harness 和音乐多任务 codec 训练代码。

## 仓库根部

- `AGENTS.md`：仓库代理规则。
- `.codex/hooks.json`：Codex 生命周期 hook 配置；命令指向 `agent-code/scripts/codex-hook.sh`。
- `agent-code/`：完全由机器管理的 agent harness 代码根目录。
- `agent-code/scripts/agent/`：显式 preflight、impact 和验证命令。
- `agent-code/scripts/codex-hook.sh`：生命周期提醒 hook。
- `agent-code/tests/agent/`：agent harness 测试。
- `bash/eval_mossland_codec_checkpoint.sh`：旧 Mossland codec Lightning checkpoint 评测流水线，面向已归档的 `scripts/_archive/mossland_codec_old/` 评测/推理栈；当前新 `scripts/mossland_codec/` 训练包还没有迁入旧 full eval pipeline。该脚本随旧栈归档，按需参考。
- `bash/push_oss_files.sh`、`bash/pull_oss_files.sh`：使用 `scripts/tools/oss_tools/bin/rclone` 和本机 `rclone.conf` 在本地与 OSS 之间同步；支持命令行参数或 `LOCAL_SRC/OSS_DST/OSS_SRC/LOCAL_DST/TRANSFERS/CHECKERS` 覆盖。源是目录时使用 `rclone copy` 做目录同步；源是单文件时使用 `rclone copyto` 直传文件。目标已存在为目录或以 `/` 结尾时自动追加源文件名，否则按显式文件路径写入，避免把目标文件名建成目录。
- `bash/prepare_seperation/node0.sh` 到 `node3.sh`：4 台机器多机多卡 separation 预处理启动脚本；每台机器 8 卡，总 `--num-shards 32`，每张 GPU 一个独立进程，使用全局 `--shard-id`，日志写入 `NETEASE_SPIDER_SEPERATION_NEW/_logs/prepare_separation_multinode/`。
- `bash/start_train.sh`：单机 8 卡 Mossland codec 训练入口，调用 `python -m scripts.train experiment=mossland-codec trainer.devices=8`。
- `bash/start_train_multinode.sh`：Mossland codec 单机/多节点训练入口。无平台 `PET_*` 环境变量时默认单机 8 卡：`PET_NPROC_PER_NODE=8`、`PET_NNODES=1`、`PET_NODE_RANK=0`、`MASTER_ADDR=127.0.0.1`、`MASTER_PORT=29500`；平台提供 `PET_MASTER_ADDR/PET_MASTER_PORT/PET_NPROC_PER_NODE/PET_NNODES/PET_NODE_RANK` 时映射到 Lightning 需要的 `MASTER_ADDR/MASTER_PORT/NODE_RANK`，并传入 `trainer.devices` 与 `trainer.num_nodes`。正常模式下每个节点启动一个父进程，由 Lightning 在本节点派生本地 GPU 进程；`DRY_RUN=1` 只打印命令。
- `scripts/train.py`：Hydra/Lightning 训练入口。入口会先显式 `data.setup()` 并构造 train/val dataloader，再把 dataloader 传给 `trainer.fit()`；不要把当前 `Experiment_Dataset` 直接作为 `datamodule` 传入，否则 Lightning 会为 no-op `prepare_data()` 创建额外 Gloo barrier，在 128 rank 规模容易触发 `Gloo connectFullMesh failed`。
- `scripts/codec_common/`：codec 实验共享的单一来源模块。`quantize.py`（`ResidualVectorQuantize`）和 `training_base.py`（`CodecTrainingBase`、`add_noise`、`get_sigma_continuous`、`pseudo_huber_loss`）历史上在 mossland_codec、music2latent、same_flow、same_flow_debug 下逐字节复制多份，现统一收于此处。各实验目录通过 `from scripts.codec_common.quantize import ...` / `from scripts.codec_common.training_base import ...` 导入；`moss_audio_flowcodec/quantize.py` 是不同的 DAC-style 实现，未并入。
- `scripts/mossland-codec/`：旧连字符 Mossland codec/评测包，仍可通过 `importlib` 和 Hydra target `scripts.mossland-codec.*` 使用。2026-06-23 主代码已删除 FSQ、`causal_rvq`、旧 512-d chunk-level packed RVQ 路径，以及公开配置里的 `bottleneck_type` 分支名；模型只由 `rvq_num_quantizers > 0` 决定是否启用 RVQ。Transformer encoder 内部仍输出 CoDiCodec-style `[B,chunks*128,4]` summary slots，但 RVQ 前通过 `pack_rvq_tokens()` 精确 reshape 为 `[B,64,chunks*8]`，即每 chunk 8 个 64-d token；RVQ 使用与当前 `scripts/mossland_codec` 同款 lucidrains EMA `ResidualVQ` thin wrapper，默认 32 层、1024 codebook、按 `rvq_latent_train_prob` 混合 continuous/discrete latent、RVQ aux loss 默认 0。`wrapper.MosslandCodecTrainingWrapper` 支持 `train_input_chunks` 和 `latent_time_shift_prob/max_tokens`：训练可先读 3+ chunks，按 64-d token 轴做 sub-chunk shift，再把 latent 和 target representation 裁回 2 个 decoder chunks，保持现有 `decoder_forward()`/attention mask 不变。`eval_benchmark/model_adapters.py` 是当前手动接新评测模型的优先接口：`run.py --adapter-target module:object --adapter-config ...` 可直接加载自定义 `predict(item, source, target, context)` adapter；复杂官方 baseline 才放入 `eval_benchmark/baselines/`。使用说明见 `docs/eval-benchmark-adapters.md`。`ckpt/mosslandcodec0617` 已替换为新代码可 strict load 的 rvq64 checkpoint/config；旧 512-d/128层 RVQ 大 checkpoint hardlink 备份为 `checkpoint_legacy_512rvq.ckpt`，旧 config 备份为 `config_legacy_512rvq.yaml` 和更早的 `config_legacy_fsq.yaml`；同样的新导出目录为 `ckpt/mosslandcodec0617_rvq64/`。
- `scripts/_archive/`：已归档、不参与当前训练的历史代码。`mossland_codec_old/`（旧 Mossland codec 实现与 `eval_benchmark/` 评测/推理栈，含全部 baseline 适配器和飞书表格生成脚本）、`mossland-a2a/`（A2A 分离 wrapper）。`mossland-a2a/` 依赖 rebuild 时删除的连字符 `scripts.mossland-codec` 模块，已无法直接运行；需复查历史指标或旧 checkpoint eval 时读 `mossland_codec_old/eval_benchmark/`，新入口不要依赖它。对应废弃实验配置归档在 `scripts/configs/experiment/_archive/`。
- `scripts/codicodec/`：当前恢复的 CoDiCodec 训练包，公开模型是 `models.UNet`，wrapper 是 `wrapper.CoDiCodecTrainingWrapper`，实验入口 `python -m scripts.train experiment=codicodec`。当前 `scripts/configs/experiment/codicodec.yaml` 是 48 kHz stereo fixed-PT overfit 口径：`hop_size=960,spec_length=32,target_length=93120`，3 个 12.5 Hz chunk；`num_latents=128,bottleneck_channels=4,rvq_dim=64`，同一 chunk 内 `128*4` reshape 成 8 个 64-d RVQ/LLM token。旧 pair/AR 训练与推理已移除，公开接口可接整段 waveform/latent，内部按 `spec_length` 拆 chunk 做 chunk-local Transformer，再拼回时间轴。当前 first-stage continuous overfit 关闭 RVQ、latent shift 和 JVP consistency，使用 `direct_denoise_mode=zero_tmax`、`decode_initial_state=zero`、`direct_detach_encoder=true`、AdamW，先训练 decoder 从固定 encoder latent 做 deterministic reconstruction；`decode(initial_state="noise")` 保留但 first-stage 指标不要用它。`transformer_layers.py` 支持 block residual 非零初始化，`UNet.pre_decoder` 和 denoising `decoder` 使用该路径以便 latent token 从启动时就能影响 x token。`eval_overfit.py` 顺序读取 dataset，支持 `--sub-length` 和 `--initial-state`；`debug_overfit.py` 用于单样本梯度、latent 敏感性和 optimizer 诊断。demo 使用 batch audio 保存 mp3；`scripts/codicodec/inference.py` 是 legacy wrapper，只保留 continuous decode 和 RVQ codes decode 的最小整段路径，当前训练/demo 以 Hydra wrapper 为准。
- `scripts/music2latent/`：按 `tmp/music2latent-training (1)/music2latent-training` 官方 public training code 整理进本仓库 Hydra/Lightning 框架的自包含 Music2Latent consistency autoencoder。`audio.py` 实现 complex STFT real/imag、`alpha_rescale=0.65/beta_rescale=0.34`、iSTFT，并用 `center_pad=false` 保持官方 no-center-pad；64 个 STFT frame 的 waveform 长度是 `hop*64+(fac-1)*hop=34304`。`models.py` 实现 2D encoder、64-d continuous latent bottleneck、latent pyramid decoder、frequency-wise attention/scaling、U-Net cross connections、EDM `c_skip/c_out/c_in` 和 decode；`Music2Latent_sametemporal` 复用原版 forward/encode/decode/U-Net 语义，只把 encoder/decoder bottleneck 有时间局部计算的 `ResBlock(use_2d=False)` 替换为直接来自 `scripts/same/transformer.py` 的 sliding-window `TransformerBlock`，保留 `Conv1d(kernel=1)` channel projection、2D `Conv2d(kernel=3)`、频率 `(5,1)` 卷积和 U-Net 主干。`local_transformer.py` 复制/适配 `scripts/same/transformer.py` 的 sliding-window SDPA、DyT/RMSNorm、RoPE、TransformerBlock，并提供 channel-first `AxialLocalAttention2d` / `AxialLocalAttentionResBlock`；`Music2Latent_axiallocal` 只替换 denoising U-Net 中的 2D `ResBlock`，保留官方 encoder、latent pyramid decoder、down/up resampling、wrapper 和 loss，用于验证 SAME-style axial local attention 能否替代 U-Net 局部计算。代码支持 encoder hidden 上的 lucidrains EMA ResidualVQ；官方复现配置关闭 `quantizer_num_quantizers=0`，RVQ 配置则用 batch 内逐样本 mixed continuous/discrete latent 训练 denoiser，并可通过 `rvq_detach_encoder=false` 让 discrete consistency loss 回传到 encoder hidden。`data.py` 提供 `Music2LatentOfficialPTDataset` 和 `python -m scripts.music2latent.data` 预读取工具，当前 `tmp/music2latent_official_pt_10k/` 已有 10000 条 mono crop `.pt`，每条 tensor shape/storage 都是 `34304`。`wrapper.py` 是 Lightning wrapper，支持官方 RAdam、EMA、cosine warmup 到 `final_learning_rate`、10000-bin lognormal sigma weighted sampling、官方 `base_step=0.1/end_exp=3` consistency step schedule 和 pseudo-Huber loss；训练裁剪与 `encode()` 都按 no-center-pad frame 数对齐到 8 的倍数。当前实验配置按用户要求使用 `bf16-mixed`，不是官方原始 fp16 autocast；`training_base.py` 的 `fail_on_nonfinite_grad` 可单独关闭 AMP 梯度 overflow 的 fail-fast，前向/loss 非有限检查仍由 `fail_on_nonfinite` 控制。小 RVQ 验证配置仍在 `music2latent-ema-rvq-overfit10.yaml`。
- `scripts/MOSS_Audio_Tokenizer/`：本地 MOSS-Audio-Tokenizer-v2 轻量推理代码。`configuration_moss_audio_tokenizer.py` 和 `modeling_moss_audio_tokenizer.py` 定义 Hugging Face 风格 `MossAudioTokenizerConfig/Model`；`infer.py` 默认加载 `checkpoints/OpenMOSS-Team/MOSS-Audio-Tokenizer-v2`，读取 `tmp/34078087/mixture.mp3`，用 `model.encode()` + `model.decode()` 重建并保存 `tmp/34078087/mixture_reconstructed.wav`。默认 `--chunk-duration=0.96`，满足 48 kHz / `downsample_rate=3840` 的整除约束并接近 1s streaming context 上限；可用 `--codec-weight-dtype bf16 --device cuda:0` 降低显存并指定设备。
- `scripts/MOSS_Audio_Tokenizer_Flow/`：Music2Latent-compatible 的 MOSS local/streaming Transformer 替代模型。`models.py` 定义 `MossAudioTokenizerFlow`，训练 API 匹配 `scripts.music2latent.models.Music2Latent.forward(latents, x, sigma)`：外部传入 clean/noisy normalized STFT representation，模型内部把 `[B,C,F,T]` 频谱按时间展平成 frame token，再复用 `scripts.MOSS_Audio_Tokenizer.modeling_moss_audio_tokenizer.MossAudioTokenizerTransformer` 和 `MossAudioTokenizerPatchedPretransform` 做 staged encoder、latent conditioner 和 sigma-conditioned denoiser。当前 overfit Flow 配置显式 `patch_sizes=[2,2,2]`，因此 encoder/denoiser down path 是 `T -> T/2 -> T/4 -> T/8`，up path 反向 `T/8 -> T/4 -> T/2 -> T`，对应 `music2latent` 的 3 次 temporal stride-2 行为；`spec_frames_per_token=8` 只表示总 patch ratio 和 wrapper 裁剪约束。latent conditioner 会从 bottleneck latent 反向生成 `T/8,T/4,T/2,T` 多尺度 condition pyramid，并在 denoiser 每个 stage 注入；sigma embedding 也通过 per-stage projection 注入每个 stage。输入/输出两端有轻量 2D `SpectralResidualBlock`（overfit 配置 `spectral_frontend_channels=16`）保留频率-时间局部结构。默认 `causal=True`，`context` 控制 MOSS 原模块里的 local causal 感受野；当前 `context=4`。该目录当前不使用旧 Flow 的 residual consistency 训练 loop、显式 `prior_tokens` 分支、RVQ双分支、patch refiner、deterministic/stochastic sampler 方案。`wrapper.py` 提供 `MossAudioTokenizerFlowTrainingWrapper`、demo callback 和固定样本 callback；训练 step 复用 `scripts.music2latent.training_base` 的 sigma/noise/pseudo-Huber 工具自算 high/low pair loss，不再依赖已删除的 `scripts.music2latent.consistency`。最小实验配置是 `scripts/configs/experiment/music2latent-overfit10-moss-tokenizer-flow.yaml`，命令 `python -m scripts.train experiment=music2latent-overfit10-moss-tokenizer-flow`；该配置当前为 stereo：`num_channels=2, data_channels=4, continuous_dim=256`，在 `4*1024*8 -> 256` 下为 `128x` 压缩率。
- `scripts/moss_audio_flowcodec/`：DAC/DACVAE-inspired 双瓶颈 waveform codec。`layers.py` 和 `quantize.py` 从本地 `tmp/descript-audio-codec` / `tmp/dacvae` 裁剪 DAC-style Snake + weight-norm Conv1d/ConvTranspose1d、ResidualUnit、Encoder/Decoder 和 RVQ，不依赖原仓库的 `audiotools` 训练框架；`models.py` 定义 `MossAudioFlowCodec`，默认 48 kHz 双声道、总 stride `1920`（`encoder_rates=[5,4,4,4,3,2]`），因此 `2*48000 -> 25 Hz` tokens。离散瓶颈默认输出 `codes=[B,32,T/1920]`，其中 `32` 是 RVQ codebook 数，`codebook_dim` 独立可配、不绑定 32；连续瓶颈输出 `continuous=[B,32,T/1920]`，经独立 projection 进入共享 DAC-style decoder。`wrapper.py` 提供无判别器 Lightning autoencoder 训练：waveform L1 + multi-scale STFT + RVQ commitment/codebook loss，同时训练 discrete recon 和 continuous recon；变码率优先用 wrapper 的 `train_n_quantizers_choices`（如 `[4,8,16,32]`）在训练 step 采样激活码本数，推理/encode/decode 时给模型传 `n_quantizers` 选择离散码率；`quantizer_dropout` 保留 DAC 原版随机 dropout 机制。demo callback 分别保存 input、discrete、continuous 和拼接对比 wav，并保存 token `.pt`。实验配置是 `scripts/configs/experiment/moss-audio-flowcodec.yaml` 和 `moss-audio-flowcodec-overfit10.yaml`。
- `scripts/same/`：自包含 SAME (Semantically-Aligned Music Autoencoder) 实现，参考 `tmp/stable-audio-3-main`、`tmp/stable-audio-tools-main` 和 `docs/papers/same.pdf`，但运行时不 import `stable_audio_3`、`stable_audio_tools` 或 `tmp/`。保留 autoencoder 必需组件：patched waveform pretransform、Music2Latent-style STFT real/imag pretransform、Transformer Resampling Block、DyT/RMSNorm、RoPE、differential SDPA attention、SoftNorm bottleneck、`AudioAutoencoder`、`SAMEAutoencoder`、Lightning wrapper 和 demo callback；未复制 SA3 diffusion、conditioning、LoRA、optimized backend、dataset CLI 等无关代码。`SAMEAutoencoder` 只接收递归 `_target_` 实例化出的 `AudioAutoencoder`，不读取 config/checkpoint。训练配置 `scripts/configs/experiment/same.yaml` 的 `model:` 是完整递归结构，不允许用 `scripts.factory.load_model` 或 `ckpt_dir`；STFT 变体入口是 `scripts/configs/experiment/same-stft.yaml`，它用 `Music2LatentSTFTPretransform(hop_size=256)` 保持时间步与 patched pretransform 对齐，并把 encoder/decoder 边界通道改为 `2048`。SAME-L 初始化权重通过顶层 `pretrain_ckpt_path=/.../ckpt/SAME-L/checkpoint.ckpt` 加载。SAME-L 已按 factory/推理目录口径整理到 `ckpt/SAME-L/{config.yaml,checkpoint.ckpt}`，其中 `checkpoint.ckpt` 由官方 `checkpoints/SAME-L/model.safetensors` 一次性导出并给权重 key 加 `autoencoder.` 前缀；该目录仍可用于推理 helper 或 `scripts.factory.load_model()`。默认 44.1 kHz stereo、`sample_size=196608`、downsampling `4096`、latent dim `256`；验证过 factory 严格加载 SAME-L，参数量 `852127073`。训练 wrapper 已升级到公开 Stable Audio Tools autoencoder 核心：manual optimization 交替训练生成器/判别器；`wrapper.loss_config` 必须完全来自 YAML。当前 `same.yaml` 显式写官方默认 7 尺度 MRSTFT、K-weighting、stereo mid/side + left/right loss、EnCodec MS-STFT discriminator 的 relativistic paired GAN 和 feature matching；官方 auraloss 支持 phase loss 但默认不启用，当前 YAML 不写 `w_phs`。`scripts/same/losses.py`、`scripts/same/discriminators.py` 是自包含移植。论文中的 PQMF/chroma 多视图、latent diffusion/semantic/contrastive auxiliary、transformer discriminator stage 仍记录在 `docs/same-training.md` 作为后续缺口。
- `scripts/same_flow/`：自包含 Music2Latent consistency autoencoder 的 SAME local transformer 变体；运行时不 import `scripts/music2latent` 或 `scripts/same`。目录内只保留当前需要的 `audio.py`、`quantize.py`、`training_base.py`、`transformer.py`、`wrapper.py`、`eval_checkpoint.py`、`debug_train.py` 和 `models.py`；旧 `music2latent_base.py` 已删除。`models.py` 当前公开入口 `SameFlowConsistencyAutoencoder` 是 SAME-L 风格 1D frame-token 模型：STFT 表示可为官方 mono `[B,2,1024,T]` 或 stereo `[B,4,F,T]`，先经 `SpectralFrameAdapter` 按频率 patch 压到 frame token，再沿时间轴用 SAME `SameFlowResampling1d` / `SameFlowBlock` 做 encoder、decoder、denoiser 和 skip/pyramid；最终 `ZeroTokenProjection` 是 zero-init frame output head，支持 `output_residual_scale` 放大 residual head 的函数更新，用于补偿 frame-linear 输出缺少 Music2Latent 2D `conv_out` 频率共享导致的初始梯度过小。`SameFlowTrainingWrapper` 主训练/loss 已按当前 `scripts/music2latent.wrapper.Music2LatnetTrainingWrapper` 对齐：官方 10000-bin lognormal sigma sampling、same high/low noisy pair、逐元素 `pseudo_huber_loss(...)*1/(sigma_high-sigma_low)` 后 mean、RAdam/AdamW、cosine warmup 到 `final_learning_rate`，并保持 source latent override 避免重复 encode。`scripts/configs/experiment/same_flow_baseline.yaml` 复用 `music2latent.yaml` 的官方 `.pt` 数据和训练参数，只替换模型；baseline 容量约 `54.4M` 参数，`hop=512,center_pad=false,output_residual_scale=64.0`。新增 `scripts/configs/experiment/music2latent-same-1d-patch.yaml` 是用户要求的第二条 SAME-shape 新架构线；当前默认 `hop=64,fac=4`，representation 约 `[B,2,128,528]`，`freq_patch_size=16,patch_channels=32,frame_channels=512`，4 次 time stride-2 得 latent `[B,64,33]`。该默认放松压缩率，用于先调通训练流程；300-step 对照显示 `hop=256 -> 128 -> 64` loss 逐步改善，hop64 batch64 可跑且显存约 `16GB/GPU`，后续先长跑验证再逐步压回更高压缩率。`eval_checkpoint.py` 用固定样本输出 `source/reconstruct` wav 和 `corr/SNR/LSD/latent_std` JSON，支持 raw/EMA checkpoint、`--direct-sigma`、mismatch conditioning 和 optimal-gain 诊断。`debug_train.py` 是单卡快速训练脚本。
- `scripts/same_flow_debug/`：`same_flow` 与 SAME/Music2Latent 替换实验的独立调试目录，不作为稳定主线入口。`audio.py`、`data.py`、`transformer.py` 与 `same_flow/` 同名文件当前逐字节相同（为对照 harness 保留独立副本，未 shim）；`models.py`、`wrapper.py` 是其消融变体。`music2latent_same_ablation.py` 提供 `Music2LatentSAMEAblation`，以官方 `scripts.music2latent.models.Music2Latent` 为基准，可通过 `ablation_variant` 分阶段替换 denoising U-Net 内部模块：`denoiser_resblock_same_time` 替换 ResBlock，`denoiser_attention_same_freq` 替换 ResBlock 内 attention，`denoiser_freq_resampling_same` 替换频率 resampling block，`denoiser_attention_freq_resampling_same` 及 `_down_only/_up_only` 做累计或单方向替换，`denoiser_resblock_freq_resampling_same_time` 累计 SAME freq resampling 与 local-time ResBlock 替换，`denoiser_resblock_same_time_freq` 是较重的轴向 time+freq 试验分支，`denoiser_resblock_same_local2d` / `denoiser_resblock_freq_resampling_same_local2d` 用 Conv2d-shaped 2D local attention 替换 ResBlock。`same_resblock_min_channels` 用于按 stage 只替换低分辨率/高通道 ResBlock；ResBlock 时间轴替换必须使用局部 `same_sliding_window`，当前卷积等价排查优先用 `[1,1]` 或 2D local `same_local2d_kernel_size=3`，而不是 full attention 或 8/16 窗口搜索。encoder/decoder/audio/loss/wrapper 保持 Music2Latent。实验记录在 `docs/exp/same_flow_music2latent_exp.md`。`compare_training_dynamics.py` 可在同一 batch/sigma/noise 下对比官方与候选的 loss、head activation、模块 grad norm 和可选固定 batch descent；旧 same_flow frame-token 诊断仍可通过 `experiment=same_flow_baseline` override 使用。`debug_train.py` 额外支持固定样本 probe，保留给旧 same_flow overfit 调试。

- `scripts/data_processing/`：面向实际数据处理任务的轻量入口。`separation_core.py` 是 OSS 分离 handler 使用的 RoFormer 核心模块，包含模型文件解析、`ffprobe/torchaudio` 时长预读、`torchaudio/ffmpeg` 音频加载、`.webm/.mp4` 容器抽音频、RoFormer 推理、44100 Hz stem 保存和 metadata 写入。`oss_prepare_separation.py` 是普通 `local_queue` handler，从 OSS 下载单条音频/视频到 worker 临时目录，默认大于等于 600 秒直接上传 `metadata(status=skiplong)` 并返回 `skiplong` receipt；短音频使用 worker 进程内缓存的 separator 生成 `mixture/vocals/accompaniment/metadata` 并上传到对应 OSS 输出目录，最后清理本地临时文件但保留模型。`oss_prepare_separation_pipeline.py` 使用同一 queue/state 格式，但在每张 GPU 内流水线化下载/预读、GPU 推理、MP3 保存和 OSS 上传，以提高 CPU/GPU 利用率。README 给出配置和运行示例。
- `scripts.data.datasets.SampleDataset`：raw audio dataset，支持 `max_duration_seconds` 在 `load_file()` 前用 `ffprobe` 读取容器 duration metadata 并 lazy 跳过超长文件；`music2latent.yaml` 当前设为 `300` 秒，避免 5 分钟以上 raw 音频被 `librosa.load()` 整段读入。
- `scripts.data.datasets.PreparedSeparationDataset`：直接读取 `prepare_separation.py` 产物目录的 `index.list`；显式 `index_file` 存在时启动只读 index，不扫描目录。首次缺索引时用 `.lock` 让一个进程扫描并写入 index，其余进程等待；支持固定对外 `length`、用真实 `item_dirs` 取余读取，以及通过 `rebuild_index()` 显式重新扫描并替换 `self.item_dirs`。大 index 启动优化参数：`deduplicate_index=false` 跳过 `sorted(set(...))`，`index_as_strings=true` 避免启动时给每行构造 `Path`，`index_cache=true/index_cache_file=...` 把解析后的字符串列表持久化为 pickle，适合 0617 recovered 这类 300 万行 index 的 DDP 重启场景；真正取样时会把单条字符串转回 `Path`。可用 `max_duration_seconds` 在单条 item 被选中后通过 `ffprobe` 按 `mixture.mp3` 容器时长 lazy 过滤长音频，按单任务或每 crop 任务列表只解码需要的 `mixture/vocals/accompaniment` stem 并集，供 `MosslandTaskDataset` 多任务训练使用；旧的包装式 separation stem dataset 已删除。
- `scripts.data.datasets.Musdb18HqSeparationDataset`：直接读取 MUSDB18-HQ 解压后的 `train/test/<track>/{mixture,vocals,drums,bass,other}.wav`，写入/读取 `index.list`，支持按任务只加载需要的 stem、多 crop、固定逻辑 `length` 和派生 `accompaniment=drums+bass+other`；供四轨分离训练配置使用。
- `scripts/tools/local_queue/`：共享文件系统本地任务队列工具包，提供 `TaskHandler/TaskRecord/TaskResult`、manifest bucket、lease、worker runner、monitor 和 finalize。核心一致性规则是任务可重复执行但只有当前 lease owner 能提交结果或记录失败；`write_manifest()` 不允许对已有 job 追加，避免重复 manifest。
- `scripts/tools/oss_tools/`：基于目录内 `bin/rclone` 和本机 `rclone.conf` 的 OSS 工具包，提供 `OssClient.upload_file()`、`download_file()`、`exists()`、`delete_file()` 和 `python -m scripts.tools.oss_tools.cli` 命令；`rclone.conf` 被 `.gitignore` 忽略，不应提交；代码注释里记录了 2026-06-12 对 `qz_oss2:public/zhaoguojie/Mossland/oss_tools_benchmark/` 小文件的实测耗时。
- `scripts/third_party/mel_band_roformer/`：从同事使用的 Mel-Band-Roformer-Vocal-Model 复制的最小模型实现，用于 `prepare_separation.py` 本地直推。
- `scripts/trainer_utils/`：Hydra/Lightning logger、callback 和通用训练工具。
- `tests/mossland_codec/`、`tests/mossland_codec_same/`、`tests/test_prepare_separation.py`、`tests/test_separation_dataset.py`、`tests/test_local_queue.py`、`tests/test_oss_prepare_separation.py`：Mossland codec、SAME-style codec shape/RVQ path、任务适配、separation 预处理/读取、local queue 一致性和 OSS separation handler 的轻量单元测试。
- `docs/mossland-codec.md`：Mossland codec 架构、separation 预处理和数据集接法说明。
- `docs/`：持久项目记忆。
